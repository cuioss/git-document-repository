= Log Messages for git-worktrees
:toc: left
:toclevels: 2

== Overview

The log-message catalogue of `git-worktrees`
(xref:../../doc/specification/general.adoc#GDR-GEN-4[GDR-GEN-4]). Every message at level INFO, WARN or ERROR carries a
stable identifier of the form `GIT_WORKTREES-<identifier>`, rendered by `LogRecord#resolveIdentifierString()` without
leading zeros; the identifiers follow the CUI `LogRecord` ranges (INFO 1-99,
WARN 100-199, ERROR 200-299). The messages are declared in
`de.cuioss.git.document.worktrees.GitWorktreesLogMessages`.

No message carries anything xref:../../doc/specification/general.adoc#GDR-NFR-3[GDR-NFR-3] forbids: a message names a
commit id or a refused capability, never a path, an administrative name derived from the caller's path, a branch name,
an author or committer name, an e-mail address or a commit message.
Debug and trace messages carry no identifier and are not listed.

== INFO Level (1-99)

[cols="1,1,2,2", options="header"]
|===
|ID |Component |Message |Description
|GIT_WORKTREES-1 |GIT_WORKTREES |Added a linked working tree at commit %s |Logged when `worktreeAdd` created a
linked working tree: the commit id it starts at.
|GIT_WORKTREES-2 |GIT_WORKTREES |Removed a linked working tree |Logged when `worktreeRemove` removed a linked working
tree or the administration files of a prunable one; the message carries no argument.
|GIT_WORKTREES-3 |GIT_WORKTREES |Released a branch reservation |Logged when `releaseBranchReservation` deleted the
reservation file of a branch; the message carries no argument, neither the branch name nor a path.
|===

== WARN Level (100-199)

[cols="1,1,2,2", options="header"]
|===
|ID |Component |Message |Description
|GIT_WORKTREES-100 |GIT_WORKTREES |Refused capability %s |Logged when the refusing file system refused a capability,
a present hook (`repository_hook`) or a process start (`process_execution`); the result is `REFUSED_BY_POLICY`.
|GIT_WORKTREES-101 |GIT_WORKTREES |Created commit %s, its reflog entry was not written |Logged when `commit` created
a commit in a linked working tree but could not append its reflog entries: the commit id only. The commit and its
branch are stored, so the result stays `OK` with the commit.
|GIT_WORKTREES-102 |GIT_WORKTREES |The rollback of a failed working-tree addition is incomplete |Logged when the
rollback of a refused or failed `worktreeAdd` could not undo everything the addition created, for example a created
branch still at its start commit that could not be deleted; the message carries no argument, neither the branch name
nor a path. The addition ends `FAILED` or with the outcome of the failure it rolled back.
|===

== ERROR Level (200-299)

`git-worktrees` logs no message at level ERROR: an unexpected failure is returned as the outcome `FAILED`.
