`git-testing` (module `de.cuioss.git.document.testing`, a scaffold) provides test support for consumers of the
reactor. It is a regular artifact consumed in test scope and depends on no other module of the reactor; its
third-party dependencies are listed in xref:general.adoc#GDR-GEN-1[GDR-GEN-1]. Rationale:
xref:../concepts/module-structure.adoc#_the_foundation_modules[Module Structure, The Foundation Modules].

[#GDR-TEST-1]
== GDR-TEST-1: Repository Fixtures

* The module must provide JUnit 5 fixtures for a local repository, an in-memory repository and a local remote for
  fetch and push tests.
* The fixtures must work without network access and must clean up every directory they create.

[cols="1,3"]
|===
|Fixture |Contract

|local repository |A bare repository in a temporary directory, created per test, deleted after it
|in-memory repository |A JGit in-memory repository of JGit's DFS (distributed file system) storage
(link:https://github.com/eclipse-jgit/jgit/blob/v7.8.0.202609011348-r/org.eclipse.jgit/src/org/eclipse/jgit/internal/storage/dfs/package-info.java[JGit 7.8.0, package `dfs`]: "Distributed file system based repository storage").
JGit's `org.eclipse.jgit.internal.storage.dfs.InMemoryRepository` lives in that internal package: the fixture wraps
it and exposes only `org.eclipse.jgit.lib.Repository`, so no consumer depends on the internal type
|local remote |A second bare repository addressed by a `file:` URL, which the remote policy local only admits
|===

[#GDR-TEST-2]
== GDR-TEST-2: Credential Generator

* The module must provide a `cui-test-generator` generator for transport credentials.

The planned `GitCredentialGenerator` and `GitGenerators` are to produce a user and a token for tests; the values must
be random and never real secrets.
