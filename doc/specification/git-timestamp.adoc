== Overview

_See Requirement link:../Requirements.adoc#GDR-GEN-1[GDR-GEN-1: Module Layering and Dependency Isolation]_

*Status:* PLANNED

`git-timestamp` (module `de.cuioss.git.document.timestamp`, not yet created, optional) provides the anchor provider
`rfc3161` of `git-store`'s `AnchorProvider` (see xref:git-store.adoc#_anchoring[git-store, Anchoring]): proofs from an
external RFC 3161 timestamp authority, for organisations that need a proof independent of their own operation. It is
the variant of the own timestamp `signed` of xref:git-signing.adoc#_own_timestamp[`git-signing`]; both can be active
at once. Which commits are anchored, the notes, their push and the retry belong to `git-store`. It depends on
`git-store`; its RFC 3161 client library is open and needs the owner's approval. Rationale:
xref:../concepts/evidence-and-companion-stores.adoc#_the_anchor[Evidence and Companion Stores, The Anchor].

== RFC 3161 Provider

_See Requirement link:../Requirements.adoc#GDR-TSA-1[GDR-TSA-1: RFC 3161 Anchor Provider]_

*Status:* PLANNED

* Provider id: `rfc3161`; its notes reference is `refs/notes/anchors/rfc3161`.
* Request: `TimeStampReq` with `messageImprint` = SHA-256 over the object id as lowercase ASCII hex (the same form as
  the passkey challenge of `git-signing`), `certReq = true`, a random nonce. The previous proof the store passes is not
  used.
* Proof: the DER-encoded `TimeStampToken`.
* An unreachable authority or an error response returns the outcome unavailable or failed; `git-store` keeps the
  subject pending and retries.

[cols="1,2"]
|===
|Configuration |Semantics

|`timestamp.url` |required; HTTPS URL of the timestamp authority
|`timestamp.trust` |required; certificate(s) of the authority for verification
|`timestamp.credentials` |optional; for authorities that require authentication
|===

An authority run inside the organisation counts as independent only when it lies under a responsibility other than
the Git administration and the application's operation; otherwise it proves no more than `signed`.

== Timestamp Verification

_See Requirement link:../Requirements.adoc#GDR-TSA-2[GDR-TSA-2: Timestamp Verification]_

*Status:* PLANNED

`verify` checks the token signature against `timestamp.trust` and the message imprint against the SHA-256 over the
object id as lowercase ASCII hex. Outcomes: the time the token proves, imprint mismatch, signature invalid (see
xref:error-model.adoc[Error Model]).
