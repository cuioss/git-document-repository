== Status

Proposed

== Decision

Git's hash chain is only as trustworthy as the people who can force-push. The index, the timestamps and a mirror must
follow every save without a second transaction. The question is how the store anchors the history externally and stays
consistent with what it derives.

*The decision:*

* An *outbox* walks the new commits of every branch a consumer subscribes to. It runs after a reference update the
  store performs (local mode), after a successful push (remote mode), and after a fetch that moves a subscribed branch.
  The last trigger covers a merge the Git server performs into protected `main`; a webhook or the periodic fetch
  brings it. The walk is idempotent by commit hash and keeps its progress per consumer and branch in a reference
  (`refs/meta/outbox/<consumer>/<branch>`, the branch name escaped: first every `%` as `%25`, then every `/` as
  `%2F`), so it resumes after a failure. The progress references are never pushed.
* `git-timestamp` is one consumer of the outbox, subscribed to `main`. It obtains an RFC 3161 timestamp for every new
  commit of `main` and stores the token as a note under `refs/notes/timestamps`. In remote mode it pushes the note
  right after writing it; a failed push keeps the commit pending, and the retry pushes the stored token instead of
  requesting a new one.
* A mirror to a second Git server is an optional further consumer.

See xref:../concepts/evidence-and-companion-stores.adoc[Evidence and Companion Stores].

== Alternatives rejected

=== A copy of all commits in a second store

The store copies every commit into a second store as evidence beside the repository.

*Rejected because* a copy under the control of the same operator adds no independent proof: whoever can force-push can
also rewrite the copy. An independent anchor needs a third party, which the timestamp authority is.

=== Public transparency logs (Sigstore/Rekor)

Every new commit is recorded in a transparency log such as the public Rekor instance of Sigstore.

*Rejected because* the entries of a public log are public, and internal compliance data must not leave the
organisation. A self-hosted log keeps the entries internal, but its operator is then no third party independent of
the repository's operator.

=== WORM storage as the default

The history is written to write-once storage that refuses any later change.

*Rejected as the default because* it requires infrastructure many operators lack. It stays an option where it exists.

=== Timestamps in a database

The timestamp tokens are kept in a database beside the repository.

*Rejected because* the proof would not travel with the repository.

== Consequences

=== Properties of the design

* The proof travels with the repository and is verifiable without the application.
* A later compromise of the signing key devalues only commits without a token issued before the compromise. A commit
  whose token was delayed past the compromise, for example by an unreachable authority, is as suspect as a new one.

=== Accepted costs

* A timestamp authority is a dependency at run time; the outbox retries when it is unreachable.
* A timestamp proves existence; it cannot restore a removed state.

=== When this is revisited

When a qualified timestamp service becomes mandatory or when the authority's availability blocks saves.
