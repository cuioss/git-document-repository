== Status

Accepted

== Decision

Some operators run the application without any Git server. Most run it against the Git server they already
operate. The question is whether these are two products or one.

*The decision:* one API and one code path serve both modes. The configuration says `remote: none` or names the
remote.

* In *local mode* the bare repository on the server's disk is the source of truth. The operator backs up the
  directory.
* In *remote mode* the remote repository is the source of truth. The local bare clone is a cache: a new clone
  restores every pushed state. Saving adds a fetch and a push.
* The local bare clone also holds what is never or not yet pushed: the drafts
  (xref:0003-Drafts_are_per-user_references_that_are_never_pushed.adoc[ADR-0003]), the outbox progress references,
  and the commits saved locally and notes whose push is pending. Deleting the clone loses them. The outbox then walks
  the subscribed branches again; its idempotency by commit hash
  (xref:0009-RFC_3161_timestamps_anchor_the_history_as_git_notes_written_by_a_post-commit_outbox.adoc[ADR-0009])
  skips commits whose result is already pushed.

A local repository becomes a remote one with one push. See
xref:../concepts/storage-engine.adoc#_two_modes_one_api[Storage Engine, Two Modes, One API].

== Alternatives rejected

=== The content API of the Git server instead of a clone

GitHub and GitLab offer REST APIs that create commits without a clone.

*Rejected because* the API binds the store to one vendor and runs into rate limits. A JGit clone works with every Git
server.

=== Separate implementations for local and remote

A file-based store serves local mode and a Git client serves remote mode.

*Rejected because* two implementations diverge. The local mode would then test nothing about the remote mode.

=== The local clone as a second source of truth

The local clone keeps saves that are not yet pushed and pushes them later.

*Rejected because* a second source of truth needs a backup of its own. Only drafts stay local, and they are
explicitly unsecured (see xref:0003-Drafts_are_per-user_references_that_are_never_pushed.adoc[ADR-0003]).

== Consequences

=== Properties of the design

* Tests run against a local or in-memory repository and cover the remote path.
* No `git` installation is needed; JGit creates and clones the repositories.

=== Accepted costs

* In remote mode every save pays a fetch and a push.
* The local directory needs persistent storage for drafts, outbox progress, pending commits and pending notes even in
  remote mode.

=== When this is revisited

When the latency of fetch and push per save becomes unacceptable in measurement.
