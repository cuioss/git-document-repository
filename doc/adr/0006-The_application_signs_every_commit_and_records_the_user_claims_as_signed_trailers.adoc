== Status

Proposed

== Decision

Every change must name who made it, in a way an auditor can check. Many users have no account on the Git server. The
question is how the store records identity.

*The decision:*

* A technical user pushes by default.
* The application signs every commit with its own key, through an exchangeable signer (KMS, HSM or key file).
* The commit message carries trailers: `Actor` (the pseudonym), `Actor-Issuer`, `Auth-Time`, `Auth-Context` and
  `Session` (an HMAC of the session id).
* On merge, approvals of a pull request become `Approved-by` and `Review` trailers.
* Pushing with the user's token is an optional credentials strategy.

This is level 1 of the graded traceability in xref:../concepts/identity-and-signing.adoc[Identity and Signing].

== Alternatives rejected

=== Push in each user's name only

*Rejected as the default because* every user would need an account and rights on the Git server. The evidence would
also lie in the server's audit log, not in the repository.

=== Commits signed with the user's own Git key

*Rejected because* a server-side JGit push would need the user's private key. Commits created through the server's API
are signed by the server and bind the store to one vendor.

=== `sub` and `sid` in clear text as trailers

*Rejected because* both are personal identifiers and would stay in the history for good. The pseudonym is erasable
through the keyring; the HMAC of `sid` still correlates with logs.

=== The author field only

*Rejected because* the author field is unchecked metadata. It makes no statement anyone can verify.

== Consequences

=== Properties of the design

* Integrity and origin of every commit are checkable without the Git server.
* Evidence is portable across Git servers.

=== Accepted costs

* Trust lies in the application and its key. A compromised server can sign in anyone's name.
* The signing key needs a KMS or HSM, an `allowed_signers` file with validity periods, and timestamps.

=== When this is revisited

When users routinely hold Git accounts and the operator prefers server-enforced rights.
