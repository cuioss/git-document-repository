== Status

Proposed

== Decision

Commits name a pseudonym, not a person. The mapping from pseudonym to person must exist and must be erasable. Git
keeps every old version of every file. The question is where the mapping lives without a further store.

*The decision:* envelope encryption in Git.

* Each person has a data key (DEK). Personal entries and personal fields are encrypted with it.
* `keys/keyring.enc` holds the DEK and the `sub` per pseudonym. It is encrypted with the key-encryption key (KEK).
* The KEK lies outside Git, supplied from outside and versioned.
* Erasure removes the entry, re-encrypts the keyring with KEK version n+1, commits it and destroys version n.
* Erasures are batched, for example daily.

See xref:../concepts/data-protection.adoc#_an_encrypted_keyring_in_git[Data Protection, An Encrypted Keyring in Git].

== Alternatives rejected

=== A separate store for the mapping

*Rejected because* it brings back the operating effort Git was meant to avoid: provisioning, backup, access control.

=== One fixed key for the keyring

*Rejected because* old versions of the keyring stay in the history. Whoever holds the fixed key decrypts yesterday's
version and has the erased person back.

=== Rewriting the history on erasure

*Rejected because* a rewrite breaks every clone, every signature and every timestamp.

=== One key per person without a keyring

*Rejected because* the store would need one external secret per person. The keyring reduces the external secrets to
one versioned KEK.

== Consequences

=== Properties of the design

* No further store: outside Git lies one secret.
* Pseudonymisation and crypto-shredding run on one technique.

=== Accepted costs

* Erasure is only as good as the destruction of the old KEK, backups included.
* The keyring is a hot spot for compare-and-swap.
* Whether KEK destruction counts as erasure is not settled; operators agree it with their data protection officer.

=== When this is revisited

When the keyring's compare-and-swap conflicts dominate, or when a regulator rules on crypto-shredding.
