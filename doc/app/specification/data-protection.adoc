[#CIFR-DP-1]
== CIFR-DP-1: Repository Cut

* The repository cut must be configurable; every repository declares exactly one confidentiality class and one
  retention period (xref:configuration.adoc#CIFR-CONF-2[CIFR-CONF-2]).
* The default configuration must contain `isms-core`, `isms-register`, `isms-incidents-<year>`, `samm-assessments`,
  `threat-models` and `directory`.

[cols="1,1,1,2"]
|===
|Alias |Confidentiality |Retention |Content

|`isms-core` |`public-internal` |`unlimited` |ISMS documents
|`isms-register` |`restricted` |`unlimited` |Risk register
|`isms-incidents-<year>` |`strongly-restricted` |`P5Y` |Incident reports of one year
|`samm-assessments` |`public-internal` |`unlimited` |SAMM
|`threat-models` |`restricted` |`unlimited` |Threat models
|`directory` |`public-internal` |`unlimited` |Catalogs, person entries under pseudonyms, records of erasures and of deleted repositories
|===

The incident period of `P5Y` is a default; an organisation sets its own with its data protection officer. A kind
names its repository in the `kinds.yaml` of its category. The application creates no repository on a Git server: the
operator creates the remote repository of each year and adds it to `repositories`
(xref:configuration.adoc#CIFR-CONF-2[CIFR-CONF-2]) before the year's first report. How the one kind `incident`
addresses a repository per year is an open question of
xref:../concepts/data-protection-and-repository-layout.adoc#_open_questions[Data Protection and Repository Layout].

[#CIFR-DP-2]
== CIFR-DP-2: Cross-Repository References

* A save containing a reference to another repository's entry must be rejected when the target does not exist.

Reference forms, as defined by the library: `<alias>:<kind>/<id>` for a document (`isms-register:risk/R-042`,
`samm-assessments:assessment/<ulid>`), and `<catalog>:<id>` for a catalog entry (`service:payment-api`, `role:ciso`).
The application uses the library's optional `#<fragment>` to name a part of the target document (a practice, a
threat); the existence check applies to the document
(xref:../../specification/git-forms.adoc#GDR-FORMS-8[GDR-FORMS-8]).

Schema markers: every reference field carries the library's `"format": "gdr-link"`
(xref:../../specification/git-forms.adoc#GDR-FORMS-8[GDR-FORMS-8]); a field holding a catalog reference carries in
addition `"x-catalog": "<catalog>"`, naming the catalog its target must belong to (for example
`"x-catalog": "service"`). There is no other reference marker. On save every reference field is resolved, a document
reference against the index and a catalog reference against the catalog; an unresolved reference is a field error
`REFERENCE_NOT_FOUND`. A reference into a repository the user may not read is reported as not found.

[#CIFR-DP-3]
== CIFR-DP-3: Erasure

* With the default person directory, a user with the right *administer catalogs* must be able to erase a pseudonym;
  the erasure must take effect at once.
* Every erasure must delete the person entry in a commit that records the pseudonym and the date, never the person;
  it must not rewrite history.

The erasure takes effect at once because the application runs as one instance
(xref:../concepts/application-architecture.adoc#_one_instance[Application Architecture, One Instance]): no other
process keeps showing the person.

`POST /api/v1/directory/erasures` (right `administer-catalogs`) with the pseudonym calls the library's erasure of the
active person directory. With `git`, one commit deletes the entry and records pseudonym and date in `erasures.yaml` of
the persons' repository; the history keeps the earlier versions, and the next checkpoint anchors the commit when an
anchor provider is active. A
provider for the organisation's own source returns managed-by-source; the application answers `409` with the problem
type `managed-by-source` and names no person.

[#CIFR-DP-4]
== CIFR-DP-4: Retention

* The application must list the repositories whose retention period has ended to users with the right *administer
  catalogs*; it must not rewrite history.
* On a confirmed deletion the application must remove its local repository on the volume, stop serving the
  repository and exclude it from the periodic fetch (xref:configuration.adoc#CIFR-CONF-2[CIFR-CONF-2]), also after a
  restart, until the operator removes it from the configuration; the remote repository and backup copies are deleted
  by the operator.

A daily job computes `end = created + retention` (for `isms-incidents-<year>`: 31 December of the year + retention)
and lists expired repositories in the *Due* lens. A confirmed deletion is a commit that appends the alias and the date
to `repository-deletions.yaml` in the `directory` repository; this record keeps the repository excluded after a
restart, and the next checkpoint anchors it when an anchor provider is active. The operator's duties (xref:../concepts/deployment.adoc#_operating_duties[Deployment, Operating Duties])
name the deletion of the remote repository and require backup expiry to match the period.

[#CIFR-DP-5]
== CIFR-DP-5: No Personal Details in Documents

* A field that names a person must store a pseudonym picked from the person directory, never a name.
* Fields marked free text in a schema must show a hint that personal details and interview notes do not belong there
  but in the ticket system.

A schema field with `"x-person": true` holds a pseudonym (`p-…`); validation refuses a value that is no known
pseudonym. There is no encrypted field type. Fields with `"x-free-text": true` show the hint text
`form.hint.no-personal-notes`.

[#CIFR-DP-6]
== CIFR-DP-6: Read-Access Events

* Every read of a document in a repository of class `restricted` or `strongly-restricted` must produce a log record
  with pseudonym, repository and document id for the security information and event management system (SIEM).

Every `read_document`, `GET /api/v1/documents/…` and diff on such a repository emits one `INFO` record
`CISOS_FRIEND-<n>: {pseudonym} read {repository}/{id}`, routed to the SIEM through the log shipping of the platform.
Index views emit one record per view, not per document.
