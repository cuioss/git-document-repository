The browser interface. Reasoning: xref:../concepts/web-app.adoc[Web App]. Reference implementation for structure and
visuals: link:https://github.com/plan-marshall/pm-mcp-clients/tree/main/pm-web-app[`pm-web-app`]; design rules:
link:https://github.com/plan-marshall/pm-mcp-clients/tree/main/doc/design/web-app[`doc/design/web-app`] of the same
repository. `pm-web-app` has no release; the adopted state is pinned by the commit id of `pm-mcp-clients` recorded in
the header of `src/styles/tokens.css`, and a change of the token contract is taken over deliberately.

[#TRH-WEB-1]
== TRH-WEB-1: Single-Page Application Served Same-Origin

* The web app must be a Svelte single-page application served by the application on its own origin.
* The built app must load no resource from a third-party origin.

[cols="1,3"]
|===
|Item |Value

|Framework
|Svelte 5 (runes), SvelteKit with `@sveltejs/adapter-static`, fallback `index.html`; `ssr = false`,
`prerender = false` in `src/routes/+layout.ts`

|Language and checks
|TypeScript strict, `svelte-check`, ESLint (typescript-eslint, security plugin), Prettier, stylelint

|Build
|Vite; Node version pinned in `package.json` `engines`

|Maven
|`web-app/pom.xml` with `frontend-maven-plugin`: `npm ci`, `build`, `test:ci`, `lint`, `check`; output copied to
`META-INF/resources`; a check fails the build when `index.html` or `_app/immutable` is missing

|Serving
|The Quarkus application serves the resource JAR at `/`; unknown non-API paths return `index.html`

|Development
|Vite dev server proxies `/api` to a running application
|===

[#TRH-WEB-2]
== TRH-WEB-2: Visual Language and Accessibility

* The app must use the design-token contract of `pm-web-app` with a light and a dark theme; no raw colour literal may
  appear in a view or a component (stylelint).
* Text contrast must meet WCAG 2.1 AA in both themes, verified automatically; the axe-core audit must report no
  violation of impact `serious` or `critical`.

Tokens, fonts and checks:

* `src/styles/tokens.css`: the token contract of `pm-web-app`; `:root` light, dark under `prefers-color-scheme` and
  `[data-theme]`. `src/lib/theme.ts`: light, dark, system; stored in `localStorage` key `cf_theme`.
* Inter variable font self-hosted in `static/fonts/` with its licence file; own icon set in `src/lib/icons/`.
* Contrast: an automated test computes the relative luminance of WCAG 2.1
  (link:https://www.w3.org/TR/WCAG21/#dfn-relative-luminance[definition]) for every text/background token pair in both
  themes; below 4.5:1 (3:1 for large text) fails, the thresholds of success criterion 1.4.3, level AA
  (link:https://www.w3.org/TR/WCAG21/#contrast-minimum[WCAG 2.1, 1.4.3 Contrast (Minimum)]). axe-core runs in
  `web-e2e` on every view.

[#TRH-WEB-3]
== TRH-WEB-3: Navigation

* The app must offer the lenses Due, SAMM, Threat models, Incidents, ISMS, Catalogs, Reports and Settings.
* Every object kind must have exactly one canonical address; reloading an address must restore the same view.

Canonical addresses: `/` (Due), `/samm/<scope>/<assessment>/<practice>`, `/threat-models/<service>/<model>`,
`/incidents/<year>/<incident>`, `/isms/risks/<entry>`, `/isms/documents/<id>`, `/catalogs/<catalog>/<id>`,
`/reports/<report>`, `/settings/<section>`, `/welcome` (first login) and `/<lens path>/release`. `src/lib/routes.ts`
holds `parseAddress` and `formatAddress`; route files are stubs rendering `AppRouter`.

[#TRH-WEB-4]
== TRH-WEB-4: Generated Forms

* Every document must be edited in a form generated from its category's JSON Schema; no category may have a
  hand-written view.
* The browser must validate against the same schema as the server; the server's verdict must be shown when they
  differ.

`src/lib/forms/SchemaForm.svelte` renders a JSON Schema:

[cols="1,2"]
|===
|Schema construct |Component

|`string`, `maxLength` |`Field` (text)
|`string` with `format: date-time` |`Field` (date-time)
|`enum` |`Select`
|`boolean` |`Toggle`
|`array` of objects |`DataTable` with row editor
|`x-catalog: <catalog>` (catalog reference, xref:data-protection.adoc#TRH-DP-2[TRH-DP-2]) |`CatalogPicker` over
that catalog
|`x-asciidoc: true` |`AsciiDocField` with server-rendered preview
|`x-person: true` |`PersonPicker` over the person directory; stores the pseudonym
|`x-free-text: true` |Hint `form.hint.no-personal-notes` shown with the field
|===

Validation: the same schema runs in the browser (Ajv) and in the server; the server's field errors replace the
browser's on save.

[#TRH-WEB-5]
== TRH-WEB-5: Drafts, Saving and Conflicts

* A form must save a draft no later than 5 seconds after the last change.
* A conflict must be shown with the fields that differ, each with the own and the other value; the draft must be kept.
* A save by another user to an open document must be visible within 5 seconds through the event stream.

Requests:

* Draft save: debounced, at most 5 s after the last change, `PUT /api/v1/drafts/{repository}/{id}`.
* Save: `POST /api/v1/documents/{repository}/{id}/save` with the blob ids loaded; the outcomes are those of the save
  in xref:architecture-and-modules.adoc#operation-outcomes[Architecture and Modules, Operation Outcomes]. On
  `GIT_UNAVAILABLE` the draft is kept, and the user saves again later.
* Event stream: `GET /api/v1/events` (`text/event-stream`); event `document-saved` with repository, id, fields; the
  open form refreshes the fields not edited locally.

[#TRH-WEB-6]
== TRH-WEB-6: Review and Release

* Release must show the diff of the structured data against the last released state.
* Every control whose transition requires step-up, under the shipped workflows the release control, must say so and
  start it when needed.

Requests:

* Diff: `GET /api/v1/documents/{repository}/{id}/diff?from=released` returns a structured diff of the YAML data; the
  view groups it by schema section.
* Release: `POST /api/v1/releases/{repository}/{id}`; the outcomes are those of the release in
  xref:architecture-and-modules.adoc#operation-outcomes[Architecture and Modules, Operation Outcomes];
  `STEP_UP_REQUIRED` carries the step-up address (xref:authentication.adoc#TRH-AUTH-4[Authentication, TRH-AUTH-4]).
  When the release requires step-up, the button reads "Release (confirm with MFA)".

[#TRH-WEB-7]
== TRH-WEB-7: Texts

* All user-facing text must come from the server's message catalogue in English and German.

`GET /api/v1/messages?lang=en|de` returns the catalogue as `application/json`: one object that maps every message key
(a string such as `samm.release.confirm`) to its text in the requested language; both languages hold the same keys. A
missing `lang` returns English; any other value is answered with `400`. `src/lib/i18n` caches the catalogue per
application version. A lint rule
fails on string literals in markup outside `src/lib/i18n`.

[#TRH-WEB-8]
== TRH-WEB-8: Page Security

* The app must be served with a Content Security Policy that allows no `unsafe-inline` script.
* Every state-changing request must carry the anti-CSRF header; the server must refuse one without it.
* A state-changing request whose `Origin` header is present and is not the application's own origin must be refused.
* Generated AsciiDoc output must be rendered and sanitised by the server.

[cols="1,3"]
|===
|Header |Value

|`Content-Security-Policy`
|`default-src 'self'; script-src 'self' 'sha256-<bootstrap>'; style-src 'self'; img-src 'self' data:;
connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`

|`X-Content-Type-Options`
|`nosniff`

|`Referrer-Policy`
|`no-referrer`
|===

Anti-CSRF: every non-`GET` request carries `X-CSRF-Token` with the value from `GET /api/v1/session`; the server
compares it with the session's token and answers a mismatch with `403`. Origin: a non-`GET` request with an `Origin`
header that differs from the application's own origin is answered with `403`; a request without `Origin` is decided
by the anti-CSRF header alone.

AsciiDoc: rendered by the server in safe mode; the HTML is sanitised against an allow-list before it is returned.
