The SAMM category as configuration (`categories/samm/`) plus the `ScoreCalculator` extension point. Reasoning:
link:../concepts/category-samm.adoc[SAMM]. Repository: `samm-assessments`.

[#CIFR-SAMM-1]
== CIFR-SAMM-1: Assessment Layout

* An assessment must be stored under `scopes/<scope-id>/assessments/<assessment-id>/` with `assessment.yaml`, one
  `answers/<practice-id>.yaml` per practice and `evidence.yaml`.
* Each assessment must record the SAMM model version it was taken with; `samm.yaml` must pin the available model
  versions.

[cols="2,3"]
|===
|Path |Content

|`samm.yaml`
|`models`: list of pinned SAMM model versions with source and checksum

|`scopes/<scope-id>/scope.yaml`
|`id`, `title`, `subject` (one of `team:<id>`, `service:<id>`, `organisation`)

|`scopes/<scope-id>/assessments/<assessment-id>/assessment.yaml`
|`title`, `date`, `model-version`, `state` (`draft`, `in-review`, `released`), `assessors` (pseudonyms)

|`…/answers/<practice-id>.yaml`
|Per question: `answer` (model answer id), `comment` (AsciiDoc fragment, optional)

|`…/evidence.yaml`
|List of `{practice, question, title, url}`

|`scopes/<scope-id>/targets.yaml`
|Per practice: `target` (0–3, in steps of the model), optional `due`
|===

`<assessment-id>` is a ULID; it names the assessment directory, the working branch, the release tag and the link
target (`samm-assessments:assessment/<assessment-id>`). A readable label such as `team-a 2026 Q4` is the `title`.

[#CIFR-SAMM-2]
== CIFR-SAMM-2: Scope

* A scope must refer to exactly one `team:`, `service:` or the organisation by stable catalog id.
* A save whose scope reference does not resolve in the directory must be rejected with a validation error naming the
  reference.

[#CIFR-SAMM-3]
== CIFR-SAMM-3: Joint Editing

* Saves by different users to different practices of one assessment must all succeed without a conflict.
* Concurrent saves to the same practice must yield a conflict for the later save that shows the differing questions
  with both values; the later user's draft must be kept.
* Every save must be visible to the other editors of the assessment within 5 seconds
  (link:web-app.adoc#CIFR-WEB-5[CIFR-WEB-5]).

Every save applies the draft's changes onto the tip of `refs/heads/assessments/<assessment-id>` as one commit (squash
merge in core). Conflicts are detected per practice file by blob id; the draft stays unchanged.

Transition `samm.submit`: `draft` → `in-review`, by a user with `edit`; it validates `required` of the schema. Saves
stay possible in `in-review`.

[#CIFR-SAMM-4]
== CIFR-SAMM-4: Release

* Release must produce the tag `assessments/<id>/v1` on the released state and require step-up; an assessment is
  released once.
* After release, any save to the released assessment must be rejected; a new assessment is created instead.

Transition `samm.release`: `in-review` → `released`, by a user with `approve`. The application merges into `main`,
tags `assessments/<assessment-id>/v1` and sets `state: released`; the release commit is signed and names the
releasing user in its trailers. Saves to a released assessment return `DOCUMENT_RELEASED`.

[#CIFR-SAMM-5]
== CIFR-SAMM-5: Scores and Comparison

* Scores must be computed as the OWASP SAMM toolbox of the assessment's model version computes them: answer values
  from the model's answer sets, a stream score as the sum of its answers, a practice score as the average of its
  streams, business function and overall scores as averages, without rounding.
* The application must compare two released assessments of one scope taken with the same model version and show the
  score difference per business function, practice and stream.

`ScoreCalculator` computes the scores (link:../concepts/category-samm.adoc#_release_comparison_and_targets[SAMM,
Release, Comparison and Targets]); its result is cached in the index per released tag:

* answer value: the `value` of the chosen answer in the model's answer set (0, 0.25, 0.5 or 1 in model v2.2.0); an
  unanswered question counts 0;
* stream score: the sum of the values of the stream's three questions (0 to 3);
* practice score: the average of its two stream scores;
* business function score: the average of its practice scores; overall score: the average of the business function
  scores.

`GET /api/v1/samm/{scope}/compare?from=<assessment>&to=<assessment>` returns per business function, practice and
stream: score `from`, score `to`, difference. Two assessments of different model versions are refused with
`MODEL_VERSIONS_DIFFER`.

[#CIFR-SAMM-6]
== CIFR-SAMM-6: Targets and Gaps

* A scope must hold target maturity per practice in `targets.yaml`.
* For a released assessment the application must list every practice whose score is below its target, and must offer
  to create a risk in the ISMS register for each gap.

The scope view shows the gaps of the latest released assessment by default. "Create risk" opens a new draft in
`isms-register` with a reference `samm-assessments:assessment/<id>#<practice>`.

[#CIFR-SAMM-7]
== CIFR-SAMM-7: Evidence as Links

* Evidence must be stored as absolute HTTPS URLs with a title; file upload of evidence must not be offered.
