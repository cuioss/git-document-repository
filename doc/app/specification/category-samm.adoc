== Overview
_See Requirement link:../Requirements.adoc#CIFR-SAMM-1[CIFR-SAMM-1: Assessment Layout]_

Status: PLANNED

The SAMM category as configuration (`categories/samm/`) plus the `ScoreCalculator` extension point. Reasoning:
link:../concepts/category-samm.adoc[SAMM]. Repository: `samm-assessments`.

== Layout
_See Requirements:_

* _link:../Requirements.adoc#CIFR-SAMM-1[CIFR-SAMM-1: Assessment Layout]_
* _link:../Requirements.adoc#CIFR-SAMM-2[CIFR-SAMM-2: Scope]_
* _link:../Requirements.adoc#CIFR-SAMM-7[CIFR-SAMM-7: Evidence as Links]_

Status: PLANNED

[cols="2,3"]
|===
|Path |Content

|`samm.yaml`
|`models`: list of pinned SAMM model versions with source and checksum

|`scopes/<scope-id>/scope.yaml`
|`id`, `title`, `subject` (one of `team:<id>`, `service:<id>`, `organisation`)

|`scopes/<scope-id>/assessments/<assessment-id>/assessment.yaml`
|`date`, `model-version`, `state` (`draft`, `in-review`, `released`), `assessors` (pseudonyms)

|`…/answers/<practice-id>.yaml`
|Per question: `answer` (model answer id), `comment` (AsciiDoc fragment, optional)

|`…/evidence.yaml`
|List of `{practice, question, title, url}`; `url` must match `^https://`

|`scopes/<scope-id>/targets.yaml`
|Per practice: `target` (0–3, in steps of the model), optional `due`
|===

`<assessment-id>` is a ULID; it names the assessment directory, the working branch, the release tag and the link
target (`samm-assessments:assessment/<assessment-id>`). A readable label such as `team-a 2026 Q4` is the field `title`
of `assessment.yaml`, not an id. `subject` must resolve through the directory on every save; an unresolved subject is
a field error.

== Editing
_See Requirement link:../Requirements.adoc#CIFR-SAMM-3[CIFR-SAMM-3: Joint Editing]_

Status: PLANNED

Workflow pattern: save often. Every save applies the draft's changes onto the tip of
`refs/heads/assessments/<assessment-id>` as one commit (squash merge in core). Conflicts are detected per practice
file by blob id: when another save changed the same practice file, `git-forms` compares the two versions per question;
changes to different questions are combined and the save re-applied, and a question changed on both sides is a
`CONFLICT` naming the question with both values. The draft stays unchanged.

Transition `samm.submit`: `draft` → `in-review`, signature level 1, by a user with `edit`; it validates `required` of
the schema. Saves stay possible in `in-review`.

== Release
_See Requirement link:../Requirements.adoc#CIFR-SAMM-4[CIFR-SAMM-4: Release]_

Status: PLANNED

Transition `samm.release`: `in-review` → `released`, default signature level 2. Effect: merge into `main`, tag
`assessments/<assessment-id>/v1`, `state: released`. Saves to a released assessment return `DOCUMENT_RELEASED`.

With `categories.samm.release.via-pull-request: true`
(link:configuration.adoc#_categories[Configuration, Categories]) `samm.submit` opens a pull or merge request, and
approve (release) merges it. The library records the approval as trailer, or as a signed note when the Git server
creates the merge.

== Comparison
_See Requirement link:../Requirements.adoc#CIFR-SAMM-5[CIFR-SAMM-5: Comparison over Time]_

Status: PLANNED

`GET /api/v1/samm/{scope}/compare?from=<assessment>&to=<assessment>` returns per business function, practice and
stream: score `from`, score `to`, difference. When the model versions differ, questions are mapped by id; a question
present in one version only, or with changed text, is listed under `changed-questions`.

`ScoreCalculator` computes practice and stream scores from the answers and the model; its result is cached in the index
per released tag.

== Targets
_See Requirement link:../Requirements.adoc#CIFR-SAMM-6[CIFR-SAMM-6: Targets and Gaps]_

Status: PLANNED

Gap: a practice whose score in a released assessment is below its `target`. The gaps are listed for every released
assessment; the scope view shows those of the latest released assessment by default. Per gap the view offers "Create
issue" (issue tracker integration) and "Create risk" (new draft in `isms-register` with a reference
`samm-assessments:assessment/<id>#<practice>`).
