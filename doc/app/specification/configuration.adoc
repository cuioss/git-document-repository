Two sources: `application.properties` for Quarkus runtime settings, and `cisos-friend.yaml` for the policy of the
application. Reasoning: link:../concepts/application-architecture.adoc#_configuration[Application Architecture,
Configuration].

[#CIFR-CONF-1]
== CIFR-CONF-1: Configuration

* Policy configuration must be one YAML document validated against a bundled JSON Schema; `${NAME:-default}`
  placeholders must be resolved from the environment.
* An invalid configuration must stop the boot with one log record per violation.
* `--validate-config <dir>` must validate offline and exit with `0` for a valid and non-zero for an invalid
  configuration.
* Secret values must not be representable in the YAML; the schema must accept only references (mounted file, KMS key
  id or Vault path).

=== cisos-friend.yaml

Validated against `schema/cisos-friend.schema.json` (bundled). Top-level keys:

[cols="1,1,3"]
|===
|Key |Required |Content

|`repositories`
|yes
|List of repositories (<<CIFR-CONF-2>>)

|`rights`
|yes
|Map of identity-provider group → list of `{repository, actions}`; actions from `read`, `edit`, `approve`,
`administer-catalogs`

|`oidc`
|yes
|Web login through Token Sheriff: `issuer`, `client-id`, `client-credential-ref` (client secret, or the private key
for `private_key_jwt`), `groups-claim` (default `groups`)

|`categories`
|yes
|List of the enabled categories (`samm`, `threat-models`, `incident-reports`, `isms`); their behaviour comes from
their definitions in the `categories` module only

|`step-up`
|yes
|`acr` (the `acr` value that states multi-factor authentication), `amr` (list of `amr` values accepted instead),
`max-age` (default `PT5M`) (link:authentication.adoc#CIFR-AUTH-4[Authentication, CIFR-AUTH-4])

|`signing`
|yes
|`key-ref` (commit-signing key; SSH format)

|`anchor`
|no
|Anchoring of releases and checkpoints
(link:../../concepts/evidence-and-companion-stores.adoc#_the_anchor[Evidence and Companion Stores, The Anchor]):
`provider` (default `signed`; `none` switches anchoring off), `checkpoint-interval` (ISO 8601 duration, default
`P1D`), `signed-key-ref` (the anchor key of the own timestamp; must differ from `signing.key-ref`)

|`mcp`
|yes
|`canonical-uri`, `authorization-servers`, `allowed-origins`

|`web`
|yes
|`session.idle-timeout` (default `PT30M`), `session.max-lifetime` (default `PT8H`), `information-text-ref`

|`directory`
|no
|The person directory (link:directory.adoc#CIFR-DIR-1[Directory, CIFR-DIR-1]): `persons.provider` (default `git`),
`persons.repository` (default `directory`), `confirmation-interval` (default `P12M`), `backstage` (the import of
link:directory.adoc#CIFR-DIR-6[CIFR-DIR-6])
|===

Every key ending in `-ref` accepts one of three reference forms; no key accepts a secret value:

* `file:/run/secrets/...`: a mounted file.
* `kms:<key-id>`: a key held by the KMS and used there; accepted only by the signing keys (`signing.key-ref`,
  `anchor.signed-key-ref`).
* `vault:<path>`: a secret of Vault's key-value engine; accepted by every key except the signing keys.

Placeholders: `${NAME}` and `${NAME:-default}` in any string value, resolved from the environment before validation;
an unresolved placeholder without default is a boot error.

=== Boot Validation

Before the application accepts requests, every rule runs; each violation produces one `ERROR` record, and any
violation stops the boot. Besides the schema, the rules refuse what the schema cannot see: two repositories with one
alias, a `rights` entry or `directory.persons.repository` naming an unknown alias, a `-ref` value in a form its key
does not accept, an `anchor.signed-key-ref` equal to `signing.key-ref`, and an `mcp.canonical-uri` that is not an
absolute HTTPS URI without fragment. Offline, `application --validate-config <dir>` runs the same rules and exits `0`
(valid) or `1` (invalid).

[#CIFR-CONF-2]
== CIFR-CONF-2: Repositories and Refresh

* Every repository must have a remote; a single-server setup uses a local bare repository as its remote.
* Every repository must declare its confidentiality class and its retention period, and nothing else may declare a
  retention period.
* The application must refresh every repository by a periodic fetch, default every 5 minutes, and after its own
  saves.

[cols="1,1,3"]
|===
|Field |Required |Meaning

|`alias`
|yes
|Stable alias used in references (`isms-register`); `isms-incidents-<year>` names one repository per year

|`remote`
|yes
|URL of the remote: HTTPS, or `file:` for a local bare repository

|`confidentiality`
|yes
|`public-internal`, `restricted`, `strongly-restricted`

|`retention`
|yes
|`unlimited` or an ISO 8601 period, counted from the repository's creation (for `isms-incidents-<year>` from the end
of that year)

|`credential-ref`
|for HTTPS
|Reference to the credential of the technical user, the only Git credential

|`fetch-interval`
|no
|ISO 8601 duration, default `PT5M`
|===
