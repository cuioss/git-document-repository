[#CIFR-OPS-1]
== CIFR-OPS-1: Native Image and Container

* The application must compile with `release` 25 and ship as a Quarkus native image.
* The image must be based on a digest-pinned distroless image, run as `nonroot`, carry OCI labels for version,
  revision, source and licence, and answer its health check through the binary.
* The image must be published as one index for `linux/amd64` and `linux/arm64` at `ghcr.io/cuioss/cisos-friend`.

[cols="1,3"]
|===
|Property |Value

|Builder
|`quay.io/quarkus/ubi9-quarkus-mandrel-builder-image:jdk-25` (`quarkus.native.builder-image`)

|Dockerfile
|`cisos-friend/src/main/docker/Dockerfile.native`

|Base image
|`quay.io/quarkus/quarkus-distroless-image:2.0@sha256:<digest>`; the digest is updated by a dependency bot

|User and binary
|`nonroot`; `/app/application`

|Health check
|`HEALTHCHECK CMD ["/app/application","--health-probe"]`; the binary probes its own management port and exits `0`
or `1` before Quarkus boots

|Labels
|`org.opencontainers.image.{title,description,version,revision,vendor,licenses,source,base.name}`; version and
revision from build arguments `APP_VERSION`, `APP_REVISION`

|Platforms
|`linux/amd64`, `linux/arm64`, each built natively on its own runner and joined into one index

|Name
|`ghcr.io/cuioss/cisos-friend:<version>`
|===

[#CIFR-OPS-2]
== CIFR-OPS-2: Ports and Readiness

* The application must serve HTTPS on 8443 and the management interface (readiness, liveness, metrics) on 9000.
* Readiness must report `UP` only when every configured repository has a valid local repository (fetched in this
  process or kept from an earlier fetch), the person directory is loaded and the index is built; a later fetch failure
  must not drop readiness.

[cols="1,1,2"]
|===
|Port |Protocol |Serves

|`8443`
|HTTPS
|Web app, `/api/v1`, `/mcp`, `/.well-known/oauth-protected-resource/mcp` and `/.well-known/oauth-protected-resource`

|`8080`
|HTTP
|Redirect to `8443` only

|`9000`
|HTTP (management)
|`/q/health/live`, `/q/health/ready`, `/q/metrics`
|===

Readiness checks, all required for `UP`: `repositories`, `persons`, `index`. A repository without a local copy keeps
`repositories` `DOWN` until its first fetch succeeds, so the application can start from the volume while the Git server
is unreachable.

Volume: `/app/data` holds the local repositories and the drafts. It is mounted from a persistent volume; the image
declares no volume.

== Secrets

[cols="1,2"]
|===
|Secret |Mount or reference

|TLS key and certificate
|`/run/secrets/tls/{tls.key,tls.crt}`

|OIDC client credential
|`oidc.client-credential-ref`: the client secret or the `private_key_jwt` key

|Git credential of the technical user
|`credential-ref` per repository

|Commit-signing key
|`signing.key-ref`: a `kms:` key id or a `file:` reference

|Anchor key of the own timestamp
|`anchor.signed-key-ref`: a `kms:` key id or a `file:` reference, never the commit-signing key
|===

The two `allowed_signers` files hold public keys only and are no secrets; they are mounted read-only with the
configuration directory and named by `signing.allowed-signers` and `anchor.signed-allowed-signers`
(xref:configuration.adoc#_cisos_friend_yaml[Configuration, cisos-friend.yaml]), which also lists the reference forms
each key accepts.

[#CIFR-OPS-3]
== CIFR-OPS-3: Compose Sample

* The deployment module must provide a compose sample that runs the published image with Keycloak and Gitea, and a
  check script that logs in, saves and releases a document.

Location: `deployment/compose-sample/`. Never builds an image; the image is `${CISOS_FRIEND_IMAGE}`.

[cols="1,3"]
|===
|Service |Role

|`cisos-friend`
|The application, named volume `cisos-friend-data`, configuration from `docker/cisos-friend-config/`

|`keycloak`
|Realm `cisos-friend` with users of each group, a confidential client for the web login and a client for an MCP
agent

|`gitea`
|Git server with the repositories of the default cut
|===

Scripts in `scripts/`: `start-sample.sh`, `stop-sample.sh`, `check-sample.sh` (logs in as a test user, writes a SAMM
draft, saves it, releases it with step-up, and verifies the release tag in Gitea).
