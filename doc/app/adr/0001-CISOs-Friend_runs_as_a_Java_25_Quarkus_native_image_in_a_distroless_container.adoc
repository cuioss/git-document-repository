== Status

Accepted

== Decision

CISOs-Friend needs a runtime for one server process. The process serves a web app, a REST API and an MCP endpoint. It
holds no database. The owner set the frame: Quarkus, native, Java 25, the CUI libraries, and the structure of API
Sheriff.

*The decision:* CISOs-Friend is one Quarkus application.

* `maven.compiler-plugin.release` is `25`. The parent is `de.cuioss:cui-quarkus-parent`.
* The shipped artifact is a native image. The Mandrel builder on the JDK 25 line builds it.
* The runtime image is `quay.io/quarkus/quarkus-distroless-image`, pinned by digest. The process runs as `nonroot`.
* The binary answers its own health probe. The image has no shell.
* The reactor mirrors API Sheriff: application, integration tests, deployment sample; plus the web app and its
  end-to-end tests.

The structure is described in link:../concepts/application-architecture.adoc[Application Architecture] and
link:../concepts/deployment.adoc[Deployment].

== Alternatives rejected

=== JVM mode

A JVM image starts slower and carries a larger attack surface. API Sheriff declined it for the same reasons.
*Rejected because* the application has no workload that needs JIT warm-up, and one runtime shape across the
organisation's Quarkus services is cheaper to operate.

=== Java 21

The libraries of `git-document-repository` compile for Java 21. *Rejected for the application because* it ships only
its own image. Nothing consumes it as a library. A lower target buys nothing and forbids Java 22 to 25 features.

=== A framework other than Quarkus

Spring Boot or a plain Java server would also work. *Rejected because* Token Sheriff ships Quarkus extensions for
validation and the confidential client. API Sheriff, the reference structure, is Quarkus.

== Consequences

=== Properties of the design

* One process, one image, one health probe.
* Contributors of API Sheriff find the same module layout, profiles and test lanes.

=== Accepted costs

* JGit must run in the native image. Its reflection and resource use must be registered. This is the first risk the
  integration tests retire.
* Native builds are slow. The unit lane stays on the JVM.

=== When this is revisited

* If JGit cannot run natively without disproportionate effort.
* If the organisation's runtime baseline moves past Java 25.
