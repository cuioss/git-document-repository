== Status

Accepted

== Decision

Git grants rights per repository only and keeps every version. Personal data must be deletable after their retention
period. Confidential registers must not be readable by everyone who reads a policy.

*The decision:* the application cuts its data into repositories.

* Every repository holds one confidentiality class and one retention class.
* The default cut is `isms-core`, `isms-register`, `isms-incidents-<year>`, `samm-assessments`, `threat-models` and
  `directory`. The cut is configuration.
* A retention period ends by deleting the whole repository: the remote repository and the application's local copy
  on the volume. No history is rewritten. Backup copies lie outside the application; the operator lets them expire
  with the same period.
* References across repositories use stable ids and are checked on save.

The details are in link:../concepts/data-protection-and-repository-layout.adoc[Data Protection and Repository Layout].

== Alternatives rejected

=== One repository for everything

*Rejected because* read access would be all or nothing. Deleting one year of incident reports would mean rewriting the
history of everything else.

=== Rewriting history for erasure

*Rejected because* rewriting breaks signatures, timestamps and every clone. It is expensive and leaves copies behind.

== Consequences

=== Properties of the design

* Git server rights per repository back the confidentiality class: only the technical user and the readers the
  organisation grants reach a repository.
* Erasure by retention is a repository deletion.

=== Accepted costs

* Queries across repositories need an instance that may read all of them.
* References across repositories can only be checked, not enforced by Git.

=== When this is revisited

* When rights finer than one repository become necessary.
