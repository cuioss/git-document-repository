### Layer 3 — Correct

The stated hardening is correct at the places traced: the reader, `DataNode` and `encode` bounds are consistent (a container counts 1, a scalar root 0), the number bounds have no off-by-one, overflow or sign gap (the exponent accumulation is capped, the digits are counted before `BigInteger` is built), the prefix charset is safe for a reference name and a link, the file reads are bounded before they are read, `encode` runs its checks before `ordered`, and the messages and the sanitised catch blocks carry no content or throwable. Remaining defects, by weight:

| Finding | Severity | File:line | Triggering input and effect |
|---------|----------|-----------|-----------------------------|
| L3-1 | **major** | `DataNode.java` 307, 325 | memory amplification by JSON Pointer building: `asObject()` and `asArray()` eagerly build a `DataNode` per child, each with its own pointer string `parent + "/" + key` (a full copy, re-read at 307 and 325). Trigger: a document of at most 3 Mi code points with a chain of long keys (for example 64 levels of 1000-character keys through explicit `? ` keys) ending in one mapping of 200,000 tiny keys, validated under a schema whose evaluator calls `asObject` at the deepest level (`additionalProperties` recursing through `$ref: "#"`, a common map-of-maps schema). Effect: about 64 KB x 200,000 = 12.8 GB of strings, an `OutOfMemoryError` (an `Error`, not a result) from one small document. The depth bound shrinks the product but does not remove it, and the landing neither bounds nor documents it. **The mechanism is confirmed by reading; the size and the evaluator path were not run** |
| L3-2 | minor | `SchemaChecks.java` 186 | `holdsRequired` recurses once per link of a `properties`/`items` → `$ref` chain, and the in-place bound (`InPlaceCycles.java` 60) does not apply (`properties` is no in-place edge). Trigger: a kind schema of about 60,000 flat `$defs` `a_i = {properties:{p:{$ref:a_(i+1)}}}` (nesting only about 4 deep, within 3 Mi) plus a root `{not:{$ref:a0}}` or `{unevaluatedProperties:{$ref:a0}}`. Effect: a `StackOverflowError` out of `FormSchema.parse` or `required`, not a MALFORMED result; reachable only by whoever authors the kind schema (configuration), so acceptable if schema authors are trusted, but not bounded by the 128 limit and, by the leaf's reading, not recorded in `git-forms.adoc`; the landing names it as a known open limit |
| L3-3 | minor | `MandatoryFields.java` 65 | stack depth is data depth times the in-place chain per level, not the sum: a recursive schema whose property schema leads through a chain of about 100 in-place `$ref`/`allOf` links back to itself (each chain under 128, accepted by `InPlaceCycles`) with 128-deep data gives about 12,800 `collect` frames and, in `validate`, the library's `RefEvaluator` recursion (many frames per link) over the same count. Effect: a `StackOverflowError` on a default 1 MB thread stack or a small virtual-thread stack; the document's "far from the default thread stack" holds only for short per-level chains. Not run |
| L3-4 | minor | `YamlReader.java` 395, `YamlDocumentCodec.java` 161 | reader and encoder drift on a hexadecimal integer: the reader counts digits in the source radix (limit 1000), the encoder counts the decimal digits of `BigInteger.toString()` (re-read: `requireReadable(number.toString())`). Trigger: `x: 0x` plus 831 to 1000 hexadecimal digits. Effect: `decode` succeeds, but `encode(decode(content))` throws `IllegalArgumentException` "a number with more than 1000 digits" (1000 hex digits are about 1204 decimal digits), so a stored document cannot be re-written through the codec, and the "bounds cannot drift" claim fails in this direction; untested (L2-2) |
| L3-5 | minor | `DataNode.java` 126 | `requireDataModel` is iterative and depth-bounded, so a self-containing value is refused, but a shared-subtree DAG (`x = List.of(x, x)` built 128 times) is walked as a tree: 2^128 visits, a hang in `validate`, `required` or `encode`. Trigger: an in-memory value built by a caller, never from text (the reader makes no aliases): a programming error, but contrary to "never stalls" |
| L3-6 | minor | `KindConfiguration.java` 248 | the collection namespace is keyed on the registry alias string only: two aliases that resolve to the same physical repository both hold the same collection and pass the duplicate check although they share one branch namespace; whether `RepositoryRegistry` refuses duplicate targets was not read, so not shown |
| L3-7 | info | `SchemaValidator.java` 97 | a concurrent call on a schema whose `$ref` targets an object not registered at preparation would make the library throw `SchemaNotFoundException` (a `RuntimeException`) out of `validate`; the schema checks (a reference must select an object) make it unlikely and it is untested; the thread-safety rests on the library reading (`new EvaluationContext` per call, a volatile `State` over a `ConcurrentHashMap`) |
